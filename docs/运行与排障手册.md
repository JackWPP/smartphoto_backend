# 运行与排障手册

## 1. 开发环境启动

### 1.1 基础命令
```bash
# 1) 启动基础设施
./scripts/dev-up.sh

# 2) 执行迁移（建议首次或显式检查时手动执行）
alembic upgrade head

# 3) 启动 API（会自动补一次 alembic upgrade head）
./scripts/dev-api.sh

# 4) 启动 Worker（会自动补一次 alembic upgrade head）
./scripts/dev-worker.sh
```

### 1.2 启动后检查
```bash
# 容器状态
docker compose ps

# 健康检查
curl -s http://127.0.0.1:8000/healthz
```

预期：`{"code":0,"message":"success","data":{"status":"ok"}}`

## 2. 任务链路排障

### 2.1 问题：任务长期停在 queued
排查路径：
1. Worker 是否运行
2. Worker 是否监听正确队列（`q.analysis,q.copy,q.generation`）
3. Redis 是否可连通
4. Job 是否已创建但未分发

建议检查：
```bash
# 观察 worker 日志（如果通过终端直接启动，直接看终端输出）
# 如通过 docker/pm2 部署，请查看对应日志
```

SQL 辅助：
```sql
SELECT id, job_type, status, queued_at, started_at
FROM jobs
ORDER BY created_at DESC
LIMIT 20;
```

### 2.2 问题：任务停在 running
排查路径：
1. 看 `/jobs/{id}` 中 `stage/error_code/error_message`
2. 看 `/jobs/{id}/events` 是否仍有增量事件
3. 检查上游接口可用性（50201/50202）
4. 检查存储路径可写权限（`STORAGE_ROOT`）
5. 如需核对 prompt 和参考图引用，单独调用 `/sessions/{id}/prompts/preview`
6. 若本轮走详情页独立生成，改查 `/sessions/{id}/detail-pages/prompts/preview`

建议检查：
```bash
curl -s http://127.0.0.1:8000/api/v2/jobs/<job_id>
curl -N http://127.0.0.1:8000/api/v2/jobs/<job_id>/events
curl -s -X POST http://127.0.0.1:8000/api/v2/sessions/<session_id>/prompts/preview \
  -H 'Content-Type: application/json' \
  -d '{"instruction":"主体更靠中间","include_latest_assets":true}'
curl -s -X POST http://127.0.0.1:8000/api/v2/sessions/<session_id>/detail-pages/prompts/preview \
  -H 'Content-Type: application/json' \
  -d '{"instruction":"标题更清晰","include_latest_assets":true}'
```

Step 5 策略排查：
```bash
curl -s -X POST http://127.0.0.1:8000/api/v2/sessions/<session_id>/strategy/preview \
  -H 'Content-Type: application/json' \
  -d '{"planner_instruction":"白底图更标准，主图更像参考图"}'
```

### 2.3 问题：409 并发冲突（job_already_running）
含义：同 session 或同用户已有运行中的生图任务。

排查路径：
1. 查询该 session 是否存在 `queued/running` 的生成类任务
2. 如果 Redis 可用，检查锁键是否残留

SQL 辅助：
```sql
SELECT id, session_id, user_id, job_type, status
FROM jobs
WHERE job_type IN ('generate_gallery','regenerate_gallery','global_edit','regenerate_asset','generate_detail_page')
  AND status IN ('queued','running')
ORDER BY created_at DESC;
```

Redis 辅助：
```bash
redis-cli KEYS 'lock:*:generation'
```

### 2.4 问题：上游失败（50201 / 50202）
排查路径：
1. `.env` 中 `WHATAI_API_KEY` 是否配置
2. `WHATAI_API_BASE`、模型名是否正确（默认推荐 `https://api.whatai.cc`，代码会自动补 `/v1`）
3. 网络出口是否可访问上游
4. 上游返回结构是否变更

补充说明：
- 若上游返回 `400 Bad Request`，优先检查当前模型对应的请求协议是否正确
- `gemini-*` 文本模型当前通过 Gemini 官方 `generateContent` 协议请求
- Step 2 分析与 Step 5 planner 当前都会把 session 图片以内联图像内容发给上游，不再依赖本地 URL 可被公网访问
- 主图组默认优先走 `/v1/images/edits`，把参考图 multipart 上传给上游；若上游返回 `task_id`，再轮询任务结果
- 生图轮询策略当前为同一 `task_id` 每 20 秒 1 次、最多 24 次，约 8 分钟；`NOT_START` 不视为失败
- 日志会附带上游响应正文，便于直接定位模型参数或协议不兼容
- 若上游报 `Server disconnected without sending a response.`，优先检查该次 WhatAI 任务是否已在中转后台生成成功；当前实现会尽量通过任务结果轮询与图片下载重试拿回链接，避免重复提交生图请求
- `/images/edits` 若在提交阶段发生传输层断连，当前实现会先做请求级重试；若仍失败，只对当前单张图做内部重试，不会整组重跑
- 若要排查“为什么这张图是这样生成的”，优先看 `POST /sessions/{id}/prompts/preview` 的 `prompts`、`reference_manifest` 和 `latest_assets.generation_snapshot`
- 若当前走详情页链路，优先看 `POST /sessions/{id}/detail-pages/prompts/preview` 的 `prompts`、`product_reference_manifest`、`style_reference_manifest` 和 `latest_assets.generation_snapshot`
- 若白底图失败，优先检查 `latest_assets.generation_snapshot.white_bg_validation` 或 worker 日志中的白底校验指标

说明：当前实现在无 key 时会使用占位输出，便于本地链路调试。

### 2.4.1 问题：`UndefinedColumn: column assets.generation_snapshot does not exist`
含义：代码已经升级到依赖 `assets.generation_snapshot` 的版本，但数据库仍停在旧迁移。

排查路径：
1. 执行 `./.venv/bin/alembic current`
2. 确认当前 revision 是否落后于 `./.venv/bin/alembic heads`
3. 执行 `./.venv/bin/alembic upgrade head`
4. 再次访问 `GET /sessions/{id}/results`

补充说明：
- 当前 `./scripts/dev-api.sh` 与 `./scripts/dev-worker.sh` 启动前会自动补一次迁移
- 若 API/Worker 已经在旧 schema 上运行，补完迁移后通常无需重建数据库，只需继续使用或重启进程

### 2.4.2 问题：详情页接口报缺列或缺表（如 `sessions.detail_strategy_preview` / `detail_style_images` / `assets.asset_family`）
含义：代码已经升级到包含详情页独立生成版本，但数据库仍停在旧迁移。

排查路径：
1. 执行 `./.venv/bin/alembic current`
2. 确认当前 revision 是否落后于 `./.venv/bin/alembic heads`
3. 执行 `./.venv/bin/alembic upgrade head`
4. 再次访问 `POST /sessions/{id}/detail-pages/strategy/preview`

### 2.5 问题：下载 ZIP 为空或版本不符
排查路径：
1. 先查 `GET /sessions/{id}/results` 看 `latest_result_version`
2. 下载接口是否指定了错误 `version`
3. 对应版本 `assets` 是否为 `ready`
4. 存储文件是否存在于 `STORAGE_ROOT`

SQL 辅助：
```sql
SELECT id, version_no, status, image_url
FROM assets
WHERE session_id = '<session_id>'
ORDER BY version_no DESC, display_order ASC;
```

## 3. 最小观测项（建议）
- Job 总量（按类型）
- Job 成功率/失败率（按类型）
- 平均耗时（analysis/copy/generation）
- 失败码分布（400xx/409xx/502xx）
- 单 session 的重生成次数

## 4. 联调脚本化检查清单
以下流程用于验证最短可用链路：
1. 创建会话
2. 上传图片
3. 触发分析
4. 选择平台
5. 保存 copy
6. 生成策略预览
7. 触发生图
8. 查询 job 与 SSE
9. 查询结果
10. 查看 prompt preview（可选）
11. 下载 ZIP

示例（按需替换变量）：
```bash
BASE=http://127.0.0.1:8000/api/v2
SID=$(curl -s -X POST "$BASE/sessions" | jq -r '.data.session_id')

curl -s -X POST "$BASE/sessions/$SID/images" \
  -F "file=@./demo.jpg;type=image/jpeg" \
  -F "slot_type=front" \
  -F "display_order=1"

curl -s -X POST "$BASE/sessions/$SID/analysis"
curl -s -X PUT "$BASE/sessions/$SID/platform-selection" \
  -H 'Content-Type: application/json' \
  -d '{"selected_platform_ids":["temu"],"active_platform_id":"temu"}'

curl -s -X PUT "$BASE/sessions/$SID/copy" \
  -H 'Content-Type: application/json' \
  -d '{"product_name":"测试产品","category":"测试类目","headline":"测试标题","selling_points":"卖点A","usage_scenes":"客厅","specs":"参数A","style_choice":"现代简约","style_custom":"","key_parameters":[]}'

curl -s -X POST "$BASE/sessions/$SID/strategy/preview"
curl -s -X POST "$BASE/sessions/$SID/strategy/preview" \
  -H 'Content-Type: application/json' \
  -d '{"planner_instruction":"白底图更标准，主图更像参考图"}'
JOB_ID=$(curl -s -X POST "$BASE/sessions/$SID/generations" \
  -H 'Content-Type: application/json' -d '{"instruction":null}' | jq -r '.data.job_id')

curl -s "$BASE/jobs/$JOB_ID"
curl -s "$BASE/sessions/$SID/results"
curl -s -X POST "$BASE/sessions/$SID/prompts/preview" \
  -H 'Content-Type: application/json' \
  -d '{"instruction":"主体更靠中间","include_latest_assets":true}'

# 详情页独立生成链路（可替代主图生成）
curl -s -X POST "$BASE/sessions/$SID/detail-pages/style-images" \
  -F "file=@./style.jpg;type=image/jpeg" \
  -F "display_order=1"
curl -s -X POST "$BASE/sessions/$SID/detail-pages/strategy/preview" \
  -H 'Content-Type: application/json' \
  -d '{"planner_instruction":"标题更短，版式更清晰"}'
DETAIL_JOB_ID=$(curl -s -X POST "$BASE/sessions/$SID/detail-pages/generations" \
  -H 'Content-Type: application/json' -d '{"instruction":"整体更高级"}' | jq -r '.data.job_id')
curl -s "$BASE/jobs/$DETAIL_JOB_ID"
curl -s "$BASE/sessions/$SID/detail-pages/results"
```

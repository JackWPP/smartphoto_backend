# 运行与排障手册

这份文档只做两件事：

- 给开发环境提供启动与排障索引
- 给生产环境提供问题定位命令索引

它不是生产主路径定义文档。

生产相关真相源优先级固定为：

1. [原生部署指南](./原生部署指南.md)
2. [原生运维指南](./原生运维指南.md)
3. [生产上线 SOP](./生产上线SOP.md)
4. 本文档

## 1. 开发环境启动

### 1.1 基础命令

```bash
# 1) 启动基础设施
./scripts/dev-up.sh

# 2) 执行迁移
alembic upgrade head

# 3) 启动 API
./scripts/dev-api.sh

# 4) 启动 Worker
./scripts/dev-worker.sh
```

### 1.2 无 Docker 本地开发

轻量模式：

```bash
cp .env.example .env
```

最小配置：

```env
DATABASE_URL=sqlite:///./storage/app.sqlite3
ADMIN_DATABASE_URL=sqlite:///./storage/admin.sqlite3
TASKS_EAGER=true
REDIS_URL=redis://localhost:6379/0
STORAGE_BACKEND=local
PUBLIC_BASE_URL=http://127.0.0.1:8000
CORS_ALLOW_ORIGINS=http://127.0.0.1:5173,http://localhost:5173
```

然后只启动：

```bash
./scripts/dev-api.sh
```

接近真实链路模式：

```bash
cp .env.example .env
./scripts/dev-api.sh
./scripts/dev-worker.sh
```

### 1.3 启动后检查

```bash
curl -s http://127.0.0.1:8000/healthz
curl -s http://127.0.0.1:8000/api/admin/v1/auth/health
```

## 2. 生产问题定位索引

推荐生产形态已经固定为：

- `postgres` / `redis`：`docker-compose.infra.yml`
- `api` / `worker` / `alembic`：宿主机 `systemd + .venv`

问题定位第一组命令：

```bash
cd /opt/smartphoto_backend/repo

docker compose --env-file .env.prod -f docker-compose.infra.yml ps
systemctl status smartphoto-api smartphoto-worker --no-pager -l
journalctl -u smartphoto-api -n 120 --no-pager -l
journalctl -u smartphoto-worker -n 120 --no-pager -l
grep -E '^(DATABASE_URL|REDIS_URL|STORAGE_ROOT|ADMIN_DATABASE_URL)=' \
  /opt/smartphoto_backend/shared/.env.prod.native
curl -i http://127.0.0.1:8000/healthz
```

### 2.1 API 起不来

先看：

```bash
journalctl -u smartphoto-api -n 200 --no-pager -l
```

重点排查：

- `DATABASE_URL` 是否仍指向 `postgres`
- `STORAGE_ROOT` 是否存在且为绝对路径
- `ADMIN_DATABASE_URL` 是否仍为相对路径
- `admin.sqlite3` 是否存在且权限正常

### 2.2 Worker 不消费任务

先看：

```bash
journalctl -u smartphoto-worker -n 200 --no-pager -l
docker compose --env-file .env.prod -f docker-compose.infra.yml exec -T redis redis-cli PING
```

重点排查：

- `REDIS_URL` 是否仍写成 `redis://redis:6379/0`
- Redis 容器是否正常
- Worker 是否被错误停止

### 2.3 迁移失败

```bash
journalctl -u smartphoto-migrate -n 200 --no-pager -l
```

重点排查：

- `DATABASE_URL` 是否可连通
- 本次是否误用 `--skip-migrate`
- 当前代码与数据库 schema 是否不一致

### 2.4 改了配置但没生效

如果改的是原生 env：

```bash
sudo systemctl restart smartphoto-api smartphoto-worker
```

如果改的是 systemd unit：

```bash
sudo systemctl daemon-reload
sudo systemctl restart smartphoto-api smartphoto-worker
```

### 2.5 基础设施端口冲突

在 `.env.prod` 加：

```env
POSTGRES_HOST_PORT=15432
REDIS_HOST_PORT=16379
```

然后重建 infra：

```bash
cd /opt/smartphoto_backend/repo
docker compose --env-file .env.prod -f docker-compose.infra.yml up -d postgres redis
```

同时把 `shared/.env.prod.native` 改为对应端口。

## 3. 任务链路排障

### 3.1 任务长期停在 `queued`

先排查 Worker 是否正常、Redis 是否可连、队列是否被消费。

### 3.2 任务停在 `running`

优先看：

- worker 日志
- 上游 WhatAI 请求超时
- 图片下载或轮询阶段是否卡住

### 3.3 `40901` / `40902` 并发冲突

这是锁或幂等保护生效，优先确认：

- 是否重复触发同一类 job
- 是否已有同 session 的生成任务还没结束

### 3.4 上游失败 `50201 / 50202`

先看 worker 日志中的：

- `upstream_http_status`
- `upstream_reason`
- WhatAI 返回正文

### 3.5 `UndefinedColumn` / `UndefinedTable`

这类问题先判定为数据库 schema 未跟上代码，而不是先怀疑业务逻辑。

优先处理：

```bash
cd /opt/smartphoto_backend/repo
./scripts/native-preflight.sh
sudo systemctl start smartphoto-migrate
```

## 附录：Windows Worker 适配

### 问题现象

Windows 本机上用 Celery 默认 `billiard` 多进程池，常见报错：

- `PermissionError: [WinError 5] 拒绝访问`
- `OSError: [WinError 6] 句柄无效`
- `SpawnPoolWorker-* exited with exitcode 1`

### 当前默认策略

- `scripts/dev-worker.ps1` 默认使用 `--pool=solo --concurrency=1`
- 默认消费队列：
  - `q.analysis`
  - `q.copy`
  - `q.generation.main`
  - `q.generation.detail`
  - `q.quality`

### 覆盖方式

```powershell
$env:CELERY_WORKER_POOL = "threads"
$env:CELERY_WORKER_CONCURRENCY = "4"
$env:CELERY_QUEUES = "q.analysis,q.copy,q.generation.main,q.generation.detail,q.quality"
.\scripts\dev-worker.ps1
```

恢复默认：

```powershell
Remove-Item Env:CELERY_WORKER_POOL -ErrorAction SilentlyContinue
Remove-Item Env:CELERY_WORKER_CONCURRENCY -ErrorAction SilentlyContinue
Remove-Item Env:CELERY_QUEUES -ErrorAction SilentlyContinue
.\scripts\dev-worker.ps1
```

# 详情页前端改造说明

更新时间：2026-03-30

适用范围：
- 详情页确认页
- 详情页 Prompt Debug 页
- 详情页结果页

目标：
- 不再把后端内部规划语义直接展示给用户
- 详情页模块标题与模块说明改成更成品化的业务中文
- 兼容旧字段，支持平滑切换

## 1. 这次前端需要改什么

核心改动只有一条：

- 详情页用户侧展示，默认改用后端新增的 `display_module_*` 字段
- 详情页 chip/tag 展示，默认改用后端新增的 `display_tags`

不要再直接把这些旧字段作为用户可见标题或说明：

- `panel_label`
- `panel_type`
- `panel_type_reason`
- `planner_base`
- `planner_source`

这些旧字段现在主要保留给：

- 后台排障
- Prompt Debug
- 内部调试面板

## 2. 新增字段

以下 3 个字段是这次前端的主消费字段：

- `display_module_title`
  - 用户看到的模块标题
  - 例子：`首屏亮点`、`核心概览`、`场景价值`、`细节参数`

- `display_module_kind`
  - 用户看到的模块类型说明
  - 例子：`卖点佐证`、`参数说明`、`场景价值`

- `display_module_intent`
  - 用户看到的模块意图说明
  - 例子：`突出核心卖点并补充可信佐证`

另外新增一个版本字段：

- `detail_policy_version`
  - 用来标识详情页是否已经升级到新的“语义分层”版本

另外新增一个可直接给 chip 用的字段：

- `display_tags`
  - 已经是去内部化后的中文标签列表
  - 例子：`["卖点佐证", "核心卖点", "真实局部图"]`
  - 前端不要再自己拿 `panel_type / narrative_section / visual_truth_mode` 拼 tag

## 3. 涉及接口

### 3.1 策略预览

接口：

```http
POST /api/v2/sessions/{session_id}/detail-pages/strategy/preview
```

这次变化：

- `detail_strategy_preview` 顶层新增：
  - `detail_policy_version`
- `detail_strategy_preview.panel_plan[*]` 新增：
  - `display_tags`
  - `display_module_title`
  - `display_module_kind`
  - `display_module_intent`

前端建议：

- 详情页确认页的模块标题，优先使用 `panel_plan[*].display_module_title`
- 如果需要展示一句模块用途，优先使用 `panel_plan[*].display_module_intent`

### 3.2 Prompt 预览

接口：

```http
POST /api/v2/sessions/{session_id}/detail-pages/prompts/preview
```

这次变化：

- 顶层新增：
  - `detail_policy_version`
- `prompts[*]` 新增：
  - `display_tags`
  - `display_module_title`
  - `display_module_kind`
  - `display_module_intent`

前端建议：

- Prompt Debug 页标题区默认展示 `display_module_title`
- 如果页面有“当前模块类型”文案，优先展示 `display_module_kind`
- 不要把 `panel_type` 直接显示给用户

### 3.3 详情页结果

接口：

```http
GET /api/v2/sessions/{session_id}/detail-pages/results
```

这次变化：

- 顶层新增：
  - `detail_policy_version`
- `panels[*]` 新增：
  - `display_tags`
  - `display_module_title`
  - `display_module_kind`
  - `display_module_intent`

前端建议：

- 结果页每个 panel 卡片标题默认改成 `display_module_title`
- 如果结果页要显示模块说明，优先显示 `display_module_intent`
- 不要再把 `panel_label=卖点槽位A/B/C` 这种老字段直接渲染给用户

## 4. 推荐渲染规则

### 4.1 标题显示

推荐优先级：

1. `display_module_title`
2. `panel_label`
3. `slot_id`

建议写法：

```ts
const title =
  item.display_module_title ||
  item.panel_label ||
  item.slot_id ||
  "详情模块";
```

### 4.2 模块类型说明

推荐优先级：

1. `display_tags`
2. `display_module_kind`
2. 不显示

不建议再直接显示：

- `panel_type`
- `narrative_section`
- `visual_truth_mode`
- `layout_template`

### 4.3 模块意图说明

推荐优先级：

1. `display_module_intent`
2. `panel_goal`
3. 不显示

说明：

- `panel_goal` 现在仍保留，但更偏内部规划
- 用户侧如果需要一句自然语言说明，优先用 `display_module_intent`

## 5. 兼容策略

这次后端没有删旧字段，所以前端可以分两步改：

### 第一阶段

- 先切换用户侧标题和说明到 `display_module_*`
- 保留老字段作为兜底

### 第二阶段

- Prompt Debug 或高级调试面板里再保留 `panel_type/panel_type_reason/planner_base`
- 用户主视图彻底不再展示内部规划字段

## 6. UI 侧需要避免的内容

以下字段不要直接展示在用户主视图：

- `panel_type`
- `panel_type_reason`
- `planner_base`
- `planner_source`
- `layout_template`
- `rule_modules_used`
- `visual_truth_mode`
- `narrative_section`

以下词如果来自接口，也不要直接上屏做标题：

- `卖点槽位A`
- `卖点槽位B`
- `卖点槽位C`
- `场景卖点`
- `产品类型`
- `布局模板`
- `feature_*`
- `parameter_*`
- `kv_*`
- `icon_*`

## 7. 自动升级说明

后端现在会自动重建旧的详情页 preview，触发条件包括：

- `detail_policy_version` 缺失或落后
- `display_module_*` 缺失
- 文案里还残留内部模板词

所以前端不需要要求用户手动“清空再重建”。

正常流程里，只要再次访问：

- `POST /detail-pages/strategy/preview`
- 或正式详情页生成

后端就会自动升级旧 preview。

## 8. 建议前端联调自测项

### 8.1 确认页

- 每个模块标题显示的是 `display_module_title`
- 不再出现 `卖点槽位A/B/C`
- 不再出现 `产品类型`
- 不再出现 `布局模板`

### 8.2 Prompt Debug

- 用户可见标题显示 `display_module_title`
- 调试区如果还显示内部字段，必须明确标成“调试信息”
- 不要把 `panel_type` 当作用户标题

### 8.3 结果页

- panel 标题默认显示 `display_module_title`
- panel 说明默认显示 `display_module_intent`
- 旧 session 重新进入后，标题能自动变成新的业务中文

## 10. 前端落地结论

可以直接按下面这条执行：

- 详情页用户侧所有标题与模块说明，统一切换到 `display_module_title / display_module_kind / display_module_intent`
- 详情页 chip/tag 统一切换到 `display_tags`

兼容兜底保留：

- `panel_label`
- `panel_goal`

不要再把内部规划字段当作用户展示真相源。

# SmartPhoto 原生运维指南

这份文档写给日常运维和值班救火用。它默认当前生产形态是：

- 代码目录：`/www/wwwroot/smartphoto_backend`
- API：`smartphoto-api.service`
- Worker：`smartphoto-worker.service`
- 数据库迁移：`smartphoto-migrate.service`
- Postgres/Redis：继续由 `docker-compose.infra.yml` 托管
- 原生配置文件：`/www/wwwroot/smartphoto_backend/shared/.env.prod.native`

一句话记忆：

**Docker 看 Postgres/Redis，systemd 看 API/Worker/Migrate，配置看 `.env.prod.native`。**

## 1. 每天先看什么

先进入项目目录：

```bash
cd /www/wwwroot/smartphoto_backend
```

看基础设施：

```bash
docker compose --env-file .env.prod -f docker-compose.infra.yml ps
```

看 API 和 Worker：

```bash
systemctl status smartphoto-api smartphoto-worker --no-pager -l
```

看健康检查：

```bash
curl -i http://127.0.0.1:8000/healthz
curl -i http://127.0.0.1:8000/api/admin/v1/auth/health
```

看端口有没有监听：

```bash
ss -ltnp '( sport = :8000 )'
```

正常情况下：

- `postgres` 和 `redis` 是 `Up`
- `smartphoto-api` 是 `active (running)`
- `smartphoto-worker` 是 `active (running)`
- `curl /healthz` 返回 HTTP 200
- `ss` 能看到 `0.0.0.0:8000` 或 `127.0.0.1:8000`

## 2. 日志怎么看

API 起不来、接口 500、后台打不开，先看 API：

```bash
journalctl -u smartphoto-api -n 200 --no-pager -l
```

任务不跑、生成卡住、队列异常，先看 Worker：

```bash
journalctl -u smartphoto-worker -n 200 --no-pager -l
```

迁移失败、缺字段、`UndefinedColumn`，看 Migrate：

```bash
journalctl -u smartphoto-migrate -n 200 --no-pager -l
```

如果要跟着实时滚动：

```bash
journalctl -u smartphoto-api -f
journalctl -u smartphoto-worker -f
```

## 3. 正常发版

默认走原生发布脚本：

```bash
cd /www/wwwroot/smartphoto_backend
SYSTEMCTL="sudo systemctl" ./scripts/native-deploy.sh --branch <deploy-branch>
```

它会做这些事：

- 拉最新代码
- 安装 Python 包
- 构建后台前端
- 停 API/Worker
- 跑 Alembic migration
- 启 API/Worker
- 打印 systemd 状态

只有你明确确认这次没有 Alembic migration，才允许跳过迁移：

```bash
cd /www/wwwroot/smartphoto_backend
SYSTEMCTL="sudo systemctl" ./scripts/native-deploy.sh --branch <deploy-branch> --skip-migrate
```

如果代码包含新的 `alembic/versions/*.py`，不要用 `--skip-migrate`。

## 4. 手工跑迁移

迁移服务是一次性的，跑完会退出，所以 `inactive (dead)` 不一定是失败。

执行：

```bash
sudo systemctl start smartphoto-migrate
sudo systemctl status smartphoto-migrate --no-pager -l
```

看到类似下面这种就是成功：

```text
Deactivated successfully.
Finished smartphoto-migrate.service
```

如果看到 `UndefinedTable`、`UndefinedColumn`、`failed to resolve host 'postgres'`，就去看第 11 节。

## 5. 改配置后怎么生效

原生配置文件是：

```bash
/www/wwwroot/smartphoto_backend/shared/.env.prod.native
```

改完配置后，API/Worker 不会自动重读，必须重启：

```bash
sudo systemctl restart smartphoto-api smartphoto-worker
```

如果改的是 systemd unit 文件，还要先：

```bash
sudo systemctl daemon-reload
sudo systemctl restart smartphoto-api smartphoto-worker
```

常查配置：

```bash
grep -E '^(DATABASE_URL|REDIS_URL|STORAGE_ROOT|ADMIN_DATABASE_URL|PUBLIC_BASE_URL|CORS_ALLOW_ORIGINS)=' \
  /www/wwwroot/smartphoto_backend/shared/.env.prod.native
```

原生部署里，`DATABASE_URL` 和 `REDIS_URL` 必须是 `127.0.0.1`，不要写 Docker 内网名：

```env
DATABASE_URL=postgresql+psycopg://smartphoto:<password>@127.0.0.1:5432/smartphoto
REDIS_URL=redis://127.0.0.1:6379/0
```

## 6. Redis 运维

看 Redis 是否通：

```bash
docker compose --env-file .env.prod -f docker-compose.infra.yml exec -T redis redis-cli PING
```

清当前 Redis DB：

```bash
sudo systemctl stop smartphoto-worker
docker compose --env-file .env.prod -f docker-compose.infra.yml exec -T redis redis-cli FLUSHDB
sudo systemctl start smartphoto-worker
```

清所有 Redis DB：

```bash
sudo systemctl stop smartphoto-worker
docker compose --env-file .env.prod -f docker-compose.infra.yml exec -T redis redis-cli FLUSHALL
sudo systemctl start smartphoto-worker
```

一般只用 `FLUSHDB`。`FLUSHALL` 更狠，除非你确定这个 Redis 只给 SmartPhoto 用。

## 7. 数据库备份

每次发包含 migration 的版本前，都先备份：

```bash
cd /www/wwwroot/smartphoto_backend

set -a
source .env.prod
set +a

mkdir -p backups

docker exec -e PGPASSWORD="$POSTGRES_PASSWORD" smartphoto_backend-postgres-1 \
  pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc \
  > "backups/${POSTGRES_DB}_$(date +%Y%m%d_%H%M%S).dump"

ls -lh backups | tail
```

如果要备份后台 SQLite 和本地 storage：

```bash
tar -czf "backups/shared_storage_$(date +%Y%m%d_%H%M%S).tar.gz" shared/storage
```

## 8. 回滚

如果只是 Python 逻辑或前端静态资源问题，可以回滚代码：

```bash
cd /www/wwwroot/smartphoto_backend
git fetch --all --prune
git reset --hard <known-good-commit-or-tag>

./.venv/bin/pip install .
(cd adminfront && npm install && npm run build)

sudo systemctl restart smartphoto-api smartphoto-worker
sudo systemctl status smartphoto-api smartphoto-worker --no-pager -l
```

如果这次发版已经跑了数据库迁移，要先判断 migration 是否向后兼容。不要把“回滚代码”当成“回滚数据库”。

## 9. API 起不来怎么救

先停掉重启循环：

```bash
sudo systemctl stop smartphoto-api
sudo systemctl reset-failed smartphoto-api
```

看最后的真实错误：

```bash
journalctl -u smartphoto-api -n 160 --no-pager -l
```

如果看到：

```text
sqlite3.OperationalError: unable to open database file
```

通常是后台 SQLite 目录或权限问题。直接修：

```bash
APP=/www/wwwroot/smartphoto_backend
cd "$APP"

mkdir -p "$APP/shared/storage" "$APP/logs"

if grep -q '^ADMIN_DATABASE_URL=' "$APP/shared/.env.prod.native"; then
  sed -i 's#^ADMIN_DATABASE_URL=.*#ADMIN_DATABASE_URL=sqlite:////www/wwwroot/smartphoto_backend/shared/storage/admin.sqlite3#' "$APP/shared/.env.prod.native"
else
  echo 'ADMIN_DATABASE_URL=sqlite:////www/wwwroot/smartphoto_backend/shared/storage/admin.sqlite3' >> "$APP/shared/.env.prod.native"
fi

if grep -q '^STORAGE_ROOT=' "$APP/shared/.env.prod.native"; then
  sed -i 's#^STORAGE_ROOT=.*#STORAGE_ROOT=/www/wwwroot/smartphoto_backend/shared/storage#' "$APP/shared/.env.prod.native"
else
  echo 'STORAGE_ROOT=/www/wwwroot/smartphoto_backend/shared/storage' >> "$APP/shared/.env.prod.native"
fi

chown -R smartphoto:smartphoto "$APP/shared" "$APP/logs"

sudo -u smartphoto "$APP/.venv/bin/python" - <<'PY'
import sqlite3
path = "/www/wwwroot/smartphoto_backend/shared/storage/admin.sqlite3"
conn = sqlite3.connect(path)
conn.execute("select 1")
conn.close()
print("sqlite ok:", path)
PY

sudo systemctl restart smartphoto-api
sudo systemctl status smartphoto-api --no-pager -l
```

如果看到：

```text
failed to resolve host 'postgres'
```

说明原生配置里还在用 Docker 内网名。改：

```bash
sed -i 's#@postgres:5432#@127.0.0.1:5432#g' /www/wwwroot/smartphoto_backend/shared/.env.prod.native
sudo systemctl restart smartphoto-api smartphoto-worker
```

## 10. Worker 不跑怎么救

先看状态：

```bash
systemctl status smartphoto-worker --no-pager -l
journalctl -u smartphoto-worker -n 160 --no-pager -l
```

如果 Redis 不通：

```bash
docker compose --env-file .env.prod -f docker-compose.infra.yml ps
docker compose --env-file .env.prod -f docker-compose.infra.yml up -d redis
docker compose --env-file .env.prod -f docker-compose.infra.yml exec -T redis redis-cli PING
```

如果配置里还是 `redis://redis:6379/0`，改：

```bash
sed -i 's#redis://redis:6379/0#redis://127.0.0.1:6379/0#g' /www/wwwroot/smartphoto_backend/shared/.env.prod.native
sudo systemctl restart smartphoto-worker
```

如果 worker 正在跑任务，重启会中断当前任务。非紧急情况下，先看日志确认是否正在提交上游图片请求。

## 11. 迁移问题怎么救

先看日志：

```bash
journalctl -u smartphoto-migrate -n 200 --no-pager -l
```

如果是数据库地址仍为 `postgres`：

```bash
sed -i 's#@postgres:5432#@127.0.0.1:5432#g' /www/wwwroot/smartphoto_backend/shared/.env.prod.native
sudo systemctl start smartphoto-migrate
```

如果是缺表/缺列：

```bash
sudo systemctl start smartphoto-migrate
sudo systemctl status smartphoto-migrate --no-pager -l
```

如果迁移已经成功，`status` 显示 `inactive (dead)` 是正常的。

## 12. 最小救火流程

不知道哪里坏了，就按这个顺序：

```bash
cd /www/wwwroot/smartphoto_backend

docker compose --env-file .env.prod -f docker-compose.infra.yml ps
systemctl status smartphoto-api smartphoto-worker --no-pager -l
journalctl -u smartphoto-api -n 120 --no-pager -l
journalctl -u smartphoto-worker -n 120 --no-pager -l
grep -E '^(DATABASE_URL|REDIS_URL|STORAGE_ROOT|ADMIN_DATABASE_URL)=' shared/.env.prod.native
curl -i http://127.0.0.1:8000/healthz
```

判断口诀：

- `curl` 连不上 8000：API 没起来，看 `smartphoto-api`
- Worker ready 但任务不动：看 Redis、队列和 DB 中 job 状态
- migrate 成功但 API 崩：多半是 admin SQLite 或 env 权限
- 报 `postgres` 解析失败：原生 env 还没改成 `127.0.0.1`
- 报 SQLite 打不开：修 `ADMIN_DATABASE_URL`、目录和权限

## 13. 发版前检查清单

发版前最少做：

```bash
cd /www/wwwroot/smartphoto_backend

docker compose --env-file .env.prod -f docker-compose.infra.yml ps
systemctl status smartphoto-api smartphoto-worker --no-pager -l
git status --short
git log -1 --oneline
```

如果本次包含 migration，先做 DB 备份，再发版。

发版后最少做：

```bash
curl -i http://127.0.0.1:8000/healthz
curl -i http://127.0.0.1:8000/api/admin/v1/auth/health
journalctl -u smartphoto-api -n 80 --no-pager -l
journalctl -u smartphoto-worker -n 80 --no-pager -l
```

## 14. 真正要记住的 8 条

- `docker compose -f docker-compose.infra.yml ps` 看 Postgres/Redis
- `systemctl status smartphoto-api smartphoto-worker` 看 API/Worker
- `journalctl -u smartphoto-api` 看 API 报错
- `journalctl -u smartphoto-worker` 看任务报错
- `systemctl start smartphoto-migrate` 跑数据库迁移
- `shared/.env.prod.native` 是原生服务真正读取的 env
- 原生服务连 DB/Redis 用 `127.0.0.1`，不要用 `postgres` / `redis`
- 改 env 后必须重启 `smartphoto-api` 和 `smartphoto-worker`

# 前端适配文档 v2.2.0 — text_elements 体系

## 一、新增字段

### `GET /sessions/{id}/results` 和 `GET /sessions/{id}/detail-pages/results`

每个 asset 新增 `text_elements` 和 `visible_copy_slots` 两个字段。

```json
{
  "asset_id": "...",
  "role": "primary_kv",
  "image_url": "...",
  "copy_blocks": {
    "headline": "高效净化99.9%",
    "supporting": "360环绕净吸",
    "proof_lines": ["HEPA H13滤网", "静音≤35dB"]
  },
  "visible_copy_slots": [
    {"slot": "headline", "text": "高效净化99.9%"},
    {"slot": "supporting", "text": "360环绕净吸"},
    {"slot": "label_e3", "text": "HEPA H13滤网"},
    {"slot": "label_e4", "text": "静音≤35dB"}
  ],
  "text_elements": [
    {"id": "e1", "role": "headline",  "text": "高效净化99.9%"},
    {"id": "e2", "role": "supporting","text": "360环绕净吸"},
    {"id": "e3", "role": "label",     "text": "HEPA H13滤网"},
    {"id": "e4", "role": "label",     "text": "静音≤35dB"}
  ]
}
```

## 二、前端需要改什么

### 1. 编辑框数据源：优先用 `text_elements`

```javascript
// 获取编辑数据（优先级从高到低）
function getEditFields(asset) {
  if (asset.text_elements?.length) {
    return asset.text_elements;  // v2.2.0 新格式
  }
  if (asset.visible_copy_slots?.length) {
    return asset.visible_copy_slots;  // v2.1.x 过渡格式
  }
  // 旧格式回退
  const cb = asset.copy_blocks || {};
  const fields = [];
  if (cb.headline) fields.push({ id: 'h', role: 'headline', text: cb.headline });
  if (cb.supporting) fields.push({ id: 's', role: 'supporting', text: cb.supporting });
  (cb.proof_lines || []).forEach((t, i) => fields.push({ id: `p${i}`, role: 'label', text: t }));
  (cb.matrix_lines || []).forEach((t, i) => fields.push({ id: `m${i}`, role: 'label', text: t }));
  return fields;
}
```

### 2. 渲染编辑框：遍历数组，不要写死槽位

```javascript
// 改前（写死）
<input value={copyBlocks.headline} />
<input value={copyBlocks.supporting} />
{copyBlocks.proof_lines.map(...)}

// 改后（动态）
{fields.map(f => (
  <div key={f.id}>
    <label>{roleLabel(f.role)}</label>
    <input value={f.text} onChange={e => updateField(f.id, e.target.value)} />
  </div>
))}

function roleLabel(role) {
  return { headline: '主标题', supporting: '副标题', label: '标签' }[role] || role;
}
```

### 3. 提交编辑：不变

`POST /assets/{id}/edit-text` 仍然用 `copy_blocks` 格式。前端需把编辑后的 fields 转回 `copy_blocks`：

```javascript
function fieldsToCopyBlocks(fields) {
  return {
    headline: fields.find(f => f.role === 'headline')?.text || '',
    supporting: fields.find(f => f.role === 'supporting')?.text || '',
    proof_lines: fields.filter(f => f.role === 'label').map(f => f.text),
  };
}
```

## 三、字段对照

| 字段 | 类型 | 说明 | 何时有值 |
|------|------|------|---------|
| `text_elements` | `[{id, role, text}]` | **v2.2.0 新增**，element级文字控制。每个 id 唯一 | 新 session（重启后生成） |
| `visible_copy_slots` | `[{slot, text}]` | v2.1.x 过渡字段，flat slot格式 | 新 session + 旧 session 动态解析 |
| `copy_blocks` | `{headline, supporting, proof_lines, matrix_lines}` | 旧格式，可能被截断/过滤 | 始终存在 |

**推荐策略**：`text_elements` → `visible_copy_slots` → `copy_blocks` 三级回退。

## 四、不需要改的

- 所有 POST/PUT 接口签名不变
- 生图触发流程不变
- `regenerateCopy` 流程不变（异步 + PUT /copy）
- 策略预览/覆盖接口不变
- 详情页接口不变（同样新增了这两个字段）

## 五、element role 含义

| role | 含义 | 视觉表现 |
|------|------|---------|
| `headline` | 主标题 | 最大最醒目的文字 |
| `supporting` | 副标题 | 第二醒目的文字 |
| `label` | 标签/卖点 | 小标签文字 |

## 六、注意事项

1. **API server 重启后**，新生成的 session 才有 `text_elements`。旧 session 通过 `visible_copy_slots` 回退。
2. **不要删 `copy_blocks` 的读取逻辑**，旧 session 可能只有这个字段。
3. `text_elements` 的 `id` 是稳定标识符（`e1, e2, ...`），同一张图的 element id 不会变。
